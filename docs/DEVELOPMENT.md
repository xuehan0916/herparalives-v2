## 当前可体验

游戏主界面 → 她的平行人生主入口 → 分类故事馆 → 选择故事 → 处境卡 → 阅读与选择。主界面的「我的平行人生」为辅助入口，图鉴是工具入口。各游戏屏幕支持返回和浏览器历史导航；当前体验的选择进度在切换屏幕时保留。

故事馆支持处境分类及简介、人物/标题/议题搜索、故事来源筛选、卡牌翻面、从当前结果抽一张推荐故事。推荐优先使用已发布、已审校的成熟内容，目录没有正式故事时才回退到开发样篇。

继续支持一屏一场景、字号调整、五章十五次选择、即时反馈、早期选择的后果回响、章末五维示意及回望、章末碎片、结局、选择记录、本地保存与读取。

## 入口与分类依据

2026-10-26 重新通读产品方案正文与回复，仍为 revision 222。本轮按用户明确要求，将原来堆在首页的介绍、卡牌和横幅拆成游戏主界面与独立故事馆。沿用纸色、灰绿、淡紫、衬线字体和原有插画元素。

产品讨论提出「按照处境分类，处境有简介」，具体分类尚未定稿。当前暂用工作与热爱、关系与边界、家庭与照顾、自我与成长、人生转折五类，定义在 `lib/story-catalog.ts`，可以直接调整；这些分类不是五维评分，也不代表已有对应数量的正式故事。

`content/stories/catalog.ts` 管理故事条目、一个故事所属的多个分类、推荐标记。新增故事在内容目录登记并审校后，再为目录条目添加分类。故事馆按真实数据统计数量，没有故事的分类显示空状态；不使用虚构条目填充目录。故事选择、处境卡与存档都按选中的故事读取，不再固定绑定林遥。

林遥故事为 AI 辅助原创虚构开发样篇，尚未内容审校，不属于正式策展内容。样篇用来验证流程，其分支和回望仍需进一步制作；不能作为正式的十五分钟内容验收。首页不沿用旧项目五条故事。

## 开发规则

- 五维先按 10/20 反馈采用安稳、自由、成就、关系、自我，描述角色处境，不给用户评分。
- 每条五章，每章三次选择；每章一枚碎片，取多数维度，三种不同时取最后一次。
- 五种各一枚兑换一次个人体验，每四条故事保底；沿用仓库已有纯逻辑，但当前界面不发放正式权益。
- Coach 不与碎片绑定。当前章末为预制回望，尚未实现逐路线精确的个性回望。
- 账号界面及服务端短信登录适配已实现，需配置短信服务方才能启用。服务端存档、权益兑换、分享奖励、AI 脱敏和生成、角色确认、结局五维趋势线尚待开发。未接入个人功能前不收集现实困惑。
- 本地记录逐次自动保存，可通过「我的 → 我的图鉴」恢复；浏览器清理会丢失。

## 运行

Node 22 或以上。`npm ci`，然后 `npm run dev -- --hostname 127.0.0.1`，打开 http://127.0.0.1:3000 。也保留 pnpm 工作区和锁文件；两种安装方式均需遵守 package.json / pnpm-workspace.yaml 的依赖覆盖。

检查：`npm run lint`、`npm test`、`npm run build`。测试覆盖完整十五次选择、五枚章末奖励、后果引用的有效性、处境分类、组合搜索、推荐故事选择和浏览器历史页面与进度的匹配。
